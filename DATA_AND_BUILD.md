# Data and build instructions

## Get the data

Read the [CAS usage terms](https://www.casact.org/terms-use) and the attribution
note on the [CAS data page](https://www.casact.org/publications-research/research/research-resources/loss-reserving-data-pulled-naic-schedule-p).
Use its **current Workers Compensation Data Set** link, which points to
[wkcomp_pos_98-07.csv](https://www.casact.org/sites/default/files/2026-03/wkcomp_pos_98-07.csv).
Place that file in the repository root. Do not use the earlier 2011 release
`wkcomp_pos.csv`; it has a different schema and period.

The CSV is not included in Git. Keep source data and local output tables out of
commits. Access and reuse remain subject to the source terms; this project does
not grant a data redistribution license. Attribution: data accessed from the CAS
page as compiled for CAS by S&P Global Market Intelligence.

On September 4, 2026, the supplied CSV was byte-identical to the official file:

```text
SHA-256: 8d0b02bed0939e932f9078f65266e9a398f580f90e5227cde053dd5b520affef
```

The build stops on a different checksum. Investigate a changed release before
updating the reference checksum or reusing this report's scope. The checksum
confirms file identity, not the accuracy of the original insurance filings.

## Fields and scope

The provided file has these fields:

| Fields | Use |
|---|---|
| `GRCODE`, `GRNAME`, `Single` | Company/group identity; code 388 is Federal Ins Co Grp, Single = 0. |
| `AccidentYear`, `DevelopmentYear`, `DevelopmentLag` | Integer keys; development year must equal accident year + lag - 1. |
| `CumPaidLoss` | Cumulative net paid losses and allocated expenses used in development. |
| `EarnedPremDIR`, `EarnedPremCeded`, `EarnedPremNet` | Direct and assumed, ceded, and net earned premium. Check net = direct and assumed - ceded. |
| `IncurredLosses`, `BulkLoss`, `PostedReserves2007` | Present and renamed by the script, but not used to fit paid-loss factors or validate results. |

Values are interpreted in USD thousands, consistent with Schedule P reporting.
For code 388, the actual file contains 90 records: 1998-2006 and ten lags. The
absence of 2007 for this group is documented rather than filled with an invented
row. Valuation is year-end 2007: 54 cells enter the triangle, and 36 later cells
are excluded. Both paid losses and the selected premium measure are net of
reinsurance. Projected amounts cover this paid-loss/allocated-expense measure,
not every possible unpaid expense provision.

For accident year 2001, paid losses fall from 190,882 to 178,283 at ages 6-7.
This is present in the official source. It is retained and flagged; the CSV does
not explain the cause. Transaction records or underlying filings are needed to
resolve it. The script does not automatically delete decreases or zero-denominator
records. Non-positive paired denominators stop fitting for investigation.

## Building 

System prerequisites:

- R **4.5.2**, the version recorded in `renv.lock`.
- Pandoc (available with RStudio, or install separately).
- A LaTeX distribution exposing `pdflatex`, such as TeX Live or TinyTeX.
  If installing TinyTeX yourself: `install.packages("tinytex")`, then
  `tinytex::install_tinytex()`. This is a one-time system setup, not a build step.
- Internet access for the initial package restore. On systems without matching
  package binaries, compilers and package-specific system libraries may be needed.

From the repository root, use one command:

```sh
Rscript build.R
```

In the RStudio Console, use `source("build.R")`; it launches a fresh R process
so packages already loaded in the Console cannot override the recorded versions.
The build checks the data identity and prerequisites, restores package versions,
runs tests, then writes all tables, figures and both documents. The expected
paid-decrease warning does not stop the run. Any failed check or report build
produces an error.

The lockfile pins R packages, not Pandoc, LaTeX, operating system or font versions.
`outputs/build-info.txt` and `outputs/session-info.txt` record the local tools.
Numerical reproducibility is the target; PDF byte identity across different
system tools is not promised.

## Edit and review

Edit `report/README.Rmd` or `report/report.Rmd`, then rebuild. Do not hand-edit
result numbers in `README.md` or the PDF. The report sources receive the same
objects generated by the analysis. Tables are saved as CSV under
`outputs/tables/`; monetary column names ending in `_000s` mean USD thousands.
All charts go under `figures/` as PNG files.

Tests alone: `Rscript tests/run_tests.R`, or `source("tests/run_tests.R")` in the
Console after restoring dependencies.

To intentionally change dependency versions, update `DESCRIPTION` if needed,
install the chosen versions in the project environment, and use
`renv::snapshot(prompt = FALSE)`. Run the full build and inspect its results
before accepting a changed lockfile. Routine builds only restore; they never
silently update the lockfile.
